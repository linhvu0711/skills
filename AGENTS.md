# Agents

## Rules

Read CODING_STANDARDS.md before you write or review code.

## Checks

- `scripts/check.sh` looks for leaks: absolute home paths, email addresses outside the reserved `.invalid` domain, and the words in the owner's private list at `.git/info/private-words` (local, never committed).
- `scripts/check.sh` also fails on a relative path in a skill or the shared core that points to no file. A skill's paths start at its folder; a shared core file's paths start at its own folder.
- `scripts/check.sh` fails when a `copy` or `heavy adaptation` row in `THIRD_PARTY_NOTICES.md` has no `LICENSE` next to it: `skills/<name>/LICENSE`, or `shared/LICENSE-<owner>` for a shared core file.
- `scripts/check.sh` fails when a skill has no `README.md`, or its README lacks one of `## Use it when`, `## What you get`, `## Needs`, `## Fits with`. A skill that `THIRD_PARTY_NOTICES.md` lists, itself or a file inside it, also needs `## Credits`.
- `scripts/check.sh` fails when a skill's `SKILL.md` has no frontmatter, a `name` that is not its folder name, or an empty `description`, or goes over Anthropic's limits: a body of 500 lines or more, a `description` over 1024 characters, or a `name` over 64 characters.
- `scripts/check.sh` fails when the top `AGENTS.md` has 200 lines or more.
- `scripts/check.sh` fails when a skill agent, a file in `skills/<name>/agents/*.md`, or the explorer or the runner in `shared/agents/*.md`, has no frontmatter, a `name` that is not its file name, an empty `description`, or a `tier:` or `checker:` line that is missing or unknown; or when a row of `shared/model-tiers.md` is in a bad format, a try-order cell names a company with no model at that tier, or a Claude or Codex try list does not end on its own harness. It names the file and line.
- `scripts/check.sh` fails when a skill's two settings for who may start it disagree: a `SKILL.md` with `disable-model-invocation: true` needs an `agents/openai.yaml` with `allow_implicit_invocation: false`, and the other way round.
- `scripts/check.sh` fails when a tracked file starts with `#!` but git stores it without the run bit. Fix it with `chmod +x <file>` and `git add <file>`.
- `scripts/check.sh` fails when a `.md` file in a skill, other than its `README.md`, or in `shared/` says "in Claude Code", "in Codex", or "with the Skill tool", and names the file and line. A `description:` line may name each harness's command form.
- The pre-commit hook runs `scripts/check.sh --staged` on the lines a commit adds, and the license, README, and `SKILL.md` checks on all it commits. Turn it on once per clone with `git config core.hooksPath scripts/hooks`.
- The commit-msg hook runs `scripts/check.sh --commit-msg`: a commit that changes a file under `skills/<name>/`, or a shared core file that skill reads, without `skills/<name>/README.md` fails, unless its message has a line `Readme: unchanged`. It also fails a commit whose subject, its first line that is not blank or a `#` comment, is over 50 characters, git's limit; a `Merge ` or `Revert ` subject that git writes is let through. A skill reads a shared core file when one of its files names it or its folder, when it reads another file in that core subfolder, or when a core file it reads names or includes it. That line skips only the README check; the pre-commit checks still run. The GitHub Repo check does not run it.
- `git commit --no-verify` skips both hooks. The Repo check on GitHub still runs `scripts/check.sh` on every pull request and every push to `main`.
- `scripts/adopt.sh <name>` moves a skill from `~/.agents/skills` into `skills/<name>/`, links it back, and runs the check on it. Run it from the main checkout, so the link points there.
- The post-commit, post-checkout, post-merge, and post-rewrite hooks run `scripts/link.sh` in the main checkout. It links each skill into `~/.agents/skills/<name>`, `~/.claude/skills/<name>`, and `~/.gemini/config/skills/<name>`, and writes each skill agent `skills/<name>/agents/<agent>.md`, and each shared agent `shared/agents/<agent>.md`, as `~/.claude/agents/<agent>.md` and `~/.codex/agents/<agent>.toml`, each marked as made by link.sh. It adds one entry that runs `shared/gate/subagent-gate.sh` to the `PreToolUse` hooks of `~/.claude/settings.json` and `~/.codex/hooks.json`, and leaves every other hook. It writes nothing into Antigravity's plugins folder, and removes the agent files, `plugin.json`, and `subagent-gate` key an earlier run wrote in its "skills" plugin. It links `~/.gemini/config/plugins` into each T3 Antigravity folder as `~/.t3/userdata/providers/antigravity/<id>/config/plugins`, and prints `skip: no T3 Antigravity folder in <folder>` when there is none. It removes the links and files it made that a rename or delete left with no source, and leaves a file it did not make. A new or renamed skill or skill agent needs no link by hand. In a worktree it does nothing. `scripts/link.sh --status` writes nothing and prints one tab-separated line per skill link, agent file, gate entry, and T3 plugins link: `<state> <kind> <harness> <name> <path> <folder>`, the state `ok`, `missing`, or `stale`, the folder the target's setting names (a skills or agents folder, a hook file's folder, or a T3 Antigravity folder), and a seventh field with its `skip:` words for a target that something else holds, or for each file of an agent that it cannot write. sync-harnesses reads it.
