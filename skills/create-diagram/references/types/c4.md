# C4: context, container, component

Answers, one level at a time:

- **Context**: what the system is, who uses it, what other systems it talks to. Nothing inside.
- **Container**: what separately runnable or deployable things make up the system (web app, API, worker, database, mobile app) and how they talk.
- **Component**: what modules make up one container. Same as `component.md`; use that card.

Pick one level per page. Zooming is a second page, linked from `guide`.

## Facts to collect

Context:
- The system, named as the product names it.
- People: roles that use it. From auth roles and public entry points.
- External systems: each third-party or sibling system called or calling. From SDK imports, webhook handlers, outbound HTTP clients. `path` to the client or handler.
- What each relationship carries, in one phrase: "sends invoices to", "authenticates via".

Container:
- Every process that runs on its own: apps, APIs, workers, schedulers, databases, caches, queues. From package workspaces, compose files, deploy manifests, `Procfile`, entry points. `path` to each entry point.
- Technology per container: language, framework, engine. Goes in `sub`.
- Relationships with protocol: "reads and writes, SQL", "calls, JSON/HTTPS", "publishes, AMQP".

## Draw it

| Thing | Data |
|---|---|
| Person | `actor` |
| The system (context) | `box`, `tag: "system"`, larger: `w: 200` |
| External system | `external` |
| Container | `container`, `sub` is the technology |
| Database, queue | `store`, `queue` |
| System boundary (container level) | group `boundary` named after the system |
| Relationship | edge, label is the phrase plus protocol when known: `calls · HTTPS/JSON` |

## Layout

Context: people on the left, the system in the center (`x: 1`), externals on the right and below. Container: people and externals outside the boundary group; inside, UI containers on top, APIs in the middle, data at the bottom.

## Budget

Context: 1 system, 2 to 5 people, 2 to 8 externals. Container: 3 to 10 containers.

## Pitfalls

- Mixing levels: a container inside a context diagram. One level.
- Technology labels that say what the team hopes to run. `sub` says what the entry point runs today.
