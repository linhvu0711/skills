# The orchestrator sends /ready-pr to a thread whose PR has conflicts

This amends ADR 0013. When an open PR that closes an issue in the Set has conflicts, and the thread that works on that issue has finished its turn, the orchestrator sends that thread one message: `/ready-pr <pr-url>`. It sends it once per PR head. In a parallel run, one merged PR often puts conflicts in the others, and the user had to find each one and start its fix. `/ready-pr` already rebases, follows /fix-conflicts, runs the checks, and stops at a ready PR, so the thread does the whole fix with the context it built. We chose it over a bare `/fix-conflicts`, which needs a rebase already in progress and leaves the checks unrun. The rest of ADR 0013 holds: the orchestrator sends nothing to a thread that is running, waits for the user, failed, or was interrupted, answers no question, and retries nothing.
